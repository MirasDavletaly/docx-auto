# Ночной бэкап исходного кода – на сервер

«Тест день 3»: «автобэкап: сохраняет копию, но не трогает оригинал, просто
сохраняет исходный код, чтобы не потерять всё, каждые 24 часа в 00:00, а
старый автоматом удалять». 30.09: «пусть бэкап в самом сервере хранится, в
случае чего вытащим его в другую папку или архивом».

## Что делает

Каждый день в 00:00 на вашем компьютере `scripts/backup/backup.ps1`:

1. Снимает папку проекта – всё, что не исключено `.gitignore`
   (`node_modules`, `dist`, `.env` не попадают), **включая правки, которые
   ещё не закоммичены**. Снимок собирается во временном индексе git:
   рабочие файлы, настоящий индекс и ветка не меняются (проверено: хеш
   `.git/index` и `git status` до и после одинаковые).
2. Упаковывает его в архив `.tar.gz` (около 1,3 МБ) – внутри папка
   `docflow-src-ДАТА_ВРЕМЯ`.
3. Отправляет архив на сервер по SSH.

Сервер кладёт архив в `/var/backups/docflow/source` под именем
`docflow-src-2026-10-01_000012.tar.gz` и **хранит 7 последних** – более
старые удаляет сам.

Журнал на компьютере: `%LOCALAPPDATA%\DocFlow\backup.log`.

GitHub для бэкапа больше не нужен: снимок идёт только на ваш сервер.

## Безопасность

- На сервере архивы принимает отдельный пользователь `docflow-backup` без
  пароля. Его ключ записан с `restrict,command=…`: этим ключом нельзя ни
  войти в оболочку, ни выполнить другую команду, ни пробросить порт – только
  отдать архив, посмотреть список или забрать архив
  (`deploy/backup/docflow-backup-receive.sh`).
- Сервер принимает только настоящий `.tar.gz` не больше 300 МБ и отдаёт
  только файлы архивов из своей папки (`../` и чужие имена отклоняются).
  Папка архивов закрыта для всех, кроме `docflow-backup` и root.
- Ключ бэкапа лежит на компьютере в `%LOCALAPPDATA%\DocFlow\backup_ed25519`
  без пароля – иначе ночная задача не отработает без человека. Кто получит
  этот файл, сможет положить на сервер архив или скачать архивы кода – но
  не больше. Потеряли компьютер – запустите `setup-backup.sh` с новым
  ключом, старый перестанет действовать.

## Установка

Когда сайт уже стоит на сервере (`docs/deploy.md`):

1. На компьютере, в PowerShell из папки проекта:

   ```powershell
   .\scripts\backup\install-backup-task.ps1 -Server IP_СЕРВЕРА
   ```

   Скрипт заведёт ключ бэкапа и напечатает команду для сервера:

   ```
   sudo bash /opt/docflow/deploy/backup/setup-backup.sh 'ssh-ed25519 AAAA… docflow-backup@ИМЯ-ПК'
   ```

2. Подключитесь к серверу (`ssh root@IP_СЕРВЕРА`) и выполните эту команду.

3. На компьютере запустите ту же команду из шага 1 ещё раз. Скрипт проверит
   связь, поставит задачу Windows на 00:00 и сразу снимет первый архив.

Задача работает, пока пользователь вошёл в Windows. Если в 00:00 компьютер
выключен или спит, архив снимется при следующем включении.

- Проверка вхолостую (собрать архив, ничего не отправляя):
  `.\scripts\backup\backup.ps1 -DryRun`
- Снять архив сейчас: `.\scripts\backup\backup.ps1`
- Снять задачу: `.\scripts\backup\install-backup-task.ps1 -Remove`
  (архивы на сервере остаются)
- Хранить не 7, а, например, 30 архивов – на сервере:
  `sudo bash /opt/docflow/deploy/backup/setup-backup.sh 'ключ' --keep 30`

SSH на сервере не на порту 22 – добавьте `-Port НОМЕР` в шаге 1.

## Восстановление

Рабочая папка проекта при этом не трогается.

```powershell
.\scripts\backup\restore.ps1 -List        # какие архивы есть на сервере
.\scripts\backup\restore.ps1              # последний – в папку
```

Архив скачивается в папку «DocFlow-восстановление» на рабочем столе и
распаковывается рядом: `DocFlow-восстановление\docflow-src-ДАТА_ВРЕМЯ`.

- Другой архив: `-Name docflow-src-2026-10-01_000012.tar.gz`
- Только архив, без распаковки: `-ArchiveOnly`
- Другая папка: `-To D:\Архив`

Прямо с сервера, без скриптов (под root):

```bash
ls -l /var/backups/docflow/source
mkdir -p /root/restore && tar -xzf /var/backups/docflow/source/docflow-src-2026-10-01_000012.tar.gz -C /root/restore
```

## Чего бэкап не делает

- **Не сохраняет документы и данные сайта.** Документы, персонал и учётные
  записи сейчас лежат в браузере каждого пользователя, а не на сервере и не
  в папке проекта. Их бэкап появится вместе с сервером и базой
  (`docs/plans/phase-01-server.md`).
- **Не сохраняет настройки сервера** – `deploy/.env` (хеш пароля на сайт) и
  сертификаты. Они восстанавливаются заново: `setup-server.sh` спросит
  пароль, Caddy получит сертификат сам.
- **Не отправляет код на GitHub.** Когда репозиторий станет приватным,
  основная ветка отправляется обычным `git push`.
