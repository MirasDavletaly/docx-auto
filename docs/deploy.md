# Публикация DocFlow на сервере

> **Устарело для работы с сервером API (2026-10-14).** Эта инструкция и
> `deploy/` публикуют только сайт. С 2 октября вход, учётные записи,
> компании и персонал – на сервере на Go с базой, и без них вход не
> работает. Рабочая публикация – на Synology: `docs/deploy-synology.md`.
> Для VPS `deploy/` надо дополнить сервером API и базой так же.

Инструкция по шагам: от пустого сервера до работающего сайта по адресу
`https://ваш-домен`. На всё – около часа, большая часть – ожидание DNS.

## Коротко

1. Купить сервер (Ubuntu 22.04/24.04) и направить на него домен – шаги 1–2.
   Домена нет – можно без него, см. «Если домена нет»: скрипту вместо домена
   дают IP сервера.
2. На своём компьютере собрать пакет и отправить на сервер – шаг 4.
3. На сервере – две команды:

   ```bash
   tar -xzf /opt/docflow-ДАТА-КОММИТ.tar.gz -C /opt
   sudo bash /opt/docflow/deploy/setup-server.sh
   ```

   Скрипт сам поставит Docker, откроет порты, спросит домен, почту и пароль
   на сайт, соберёт и запустит сайт, включит защиту от подбора пароля
   (fail2ban) и дождётся сертификата HTTPS.
4. Открыть `https://ваш-домен` и завести администратора – шаг 7.

Шаги 3, 5 и 6 ниже – то же самое вручную, если скрипт не подошёл.

## 0. Прочитать до начала: что именно публикуется

Публикуется **сайт в его нынешнем виде – без сервера данных**. Это значит:

- **Данные живут в браузере каждого человека.** Документы, персонал,
  учётные записи хранятся в том браузере, где с ними работали. Сотрудник на
  другом компьютере откроет сайт и увидит пустую систему с экраном «Первый
  запуск». Общей базы на всю группу пока нет – она появится с серверным
  этапом (`docs/plans/phase-01-server.md`).
- **Очистка данных браузера стирает документы.** Резервной копии данных нет.
  Работайте в одном браузере на одном компьютере, не в режиме инкогнито.
- **Защита – пароль на весь сайт.** Без него код сайта с реквизитами
  компаний (БИН, счета) скачал бы любой, кто знает адрес. Этот пароль
  спрашивает сам веб-сервер до входа в приложение.

Подходит, чтобы показывать систему и работать с ней одному человеку или
на одном компьютере. Для работы всей группы нужен серверный этап.

## 1. Что нужно

| Что | Зачем |
|---|---|
| Сервер Linux (VPS): Ubuntu 22.04 или 24.04, 1 ядро, 1 ГБ памяти, 10 ГБ диска, публичный IP | Здесь работает веб-сервер |
| Доступ по SSH под root или пользователем с `sudo` | Установка и запуск |
| Домен или поддомен, например `docs.вашакомпания.kz` (или без домена – см. ниже) | **HTTPS обязателен**: без него браузер не даёт проверять пароли, и вход не работает |
| Открытые порты 80 и 443 | Сайт и выпуск сертификата |

Сервер лучше взять с размещением в Казахстане: когда появится база с
персональными данными, закон требует хранить их там (подтвердить у юриста).

## Если домена нет

**Просто `http://IP-сервера` не подойдёт.** Сайт откроется, но покажет
«Откройте сайт по защищённому адресу»: без HTTPS браузер не даёт
проверять пароли, и ни первый запуск, ни вход не работают. Проверено в
Chrome 29.09.

Что можно без покупки домена:

| Вариант | Как | Что увидят люди |
|---|---|---|
| **Бесплатное имя для IP** (рекомендуется) | Скрипту установки (шаг «Коротко», п. 3) вместо домена введите IP сервера. Он сам возьмёт имя `1-2-3-4.sslip.io` – сервис sslip.io направляет такое имя на ваш IP, – и Caddy получит на него настоящий сертификат | Адрес `https://1-2-3-4.sslip.io`, без предупреждений браузера. Шаг 2 (A-запись) не нужен |
| `https://IP` с самоподписанным сертификатом | Нужна правка `deploy/Caddyfile` (`tls internal`) – попросите, сделаю | На каждом компьютере браузер один раз предупредит «Подключение не защищено», нужно нажать «Дополнительно → Перейти». Дальше всё работает – проверено в Chrome |

Для работы всерьёз лучше свой домен: имя sslip.io зависит от стороннего
бесплатного сервиса, и в адресе видны цифры IP. Домен `.kz` стоит
несколько тысяч тенге в год. Перейти на него потом просто: удалить
`deploy/.env` и запустить скрипт установки снова с доменом.

## 2. Домен: направить на сервер

В панели, где куплен домен, добавьте **A-запись**:

| Имя | Тип | Значение |
|---|---|---|
| `docs` (или `@` для корня домена) | A | IP сервера |

Проверка с вашего компьютера (PowerShell), когда запись разойдётся –
от нескольких минут до пары часов:

```powershell
nslookup docs.вашакомпания.kz
```

В ответе должен быть IP сервера.

## 3. Сервер: поставить Docker

Подключитесь к серверу:

```powershell
ssh root@IP_СЕРВЕРА
```

На сервере:

```bash
curl -fsSL https://get.docker.com | sh
docker compose version
```

Вторая команда должна напечатать версию – значит, Docker готов.

Если на сервере включён брандмауэр `ufw`, откройте порты:

```bash
ufw allow 80/tcp && ufw allow 443/tcp && ufw allow 443/udp
```

## 4. Ваш компьютер: собрать пакет и отправить на сервер

В PowerShell из папки проекта:

```powershell
.\scripts\deploy\pack.ps1
```

Скрипт проверит сайт (типы, тесты, сборка) и соберёт
`dist-deploy\docflow-ДАТА-КОММИТ.tar.gz`. Если есть незакоммиченные правки,
он откажется: в пакет идёт то, что проверено и лежит в истории.

Отправьте пакет на сервер (имя файла – то, что напечатал скрипт):

```powershell
scp .\dist-deploy\docflow-2026-09-25-abc1234.tar.gz root@IP_СЕРВЕРА:/opt/
```

## 5. Сервер: распаковать и настроить

```bash
mkdir -p /opt/docflow
tar -xzf /opt/docflow-2026-09-25-abc1234.tar.gz -C /opt
cd /opt/docflow/deploy
cp .env.example .env
```

Придумайте **пароль на сайт** – не короче 12 знаков – и получите его хеш:

```bash
docker run --rm caddy:2.11-alpine caddy hash-password --plaintext 'ВашПарольНаСайт'
```

Откройте настройки:

```bash
nano .env
```

и заполните:

```
DOCFLOW_DOMAIN=docs.вашакомпания.kz
DOCFLOW_ACME_EMAIL=ваша@почта.kz
DOCFLOW_AUTH_USER=docflow
DOCFLOW_AUTH_HASH='$2a$14$...хеш из предыдущей команды...'
```

Хеш – **в одинарных кавычках**: в нём есть знаки `$`. Сохранить в nano:
Ctrl+O, Enter, Ctrl+X.

## 6. Запустить

```bash
mkdir -p logs && touch logs/access.log
docker compose build --pull
docker compose up -d
docker compose logs -f
```

Первая сборка идёт несколько минут. В журнале должны появиться строки
`certificate obtained successfully` – сертификат HTTPS получен.
Выйти из журнала: Ctrl+C (сайт продолжит работать).

## 7. Проверить

1. Откройте `https://docs.вашакомпания.kz`. Браузер спросит логин и пароль
   сайта – `docflow` и пароль из шага 5.
2. Откроется «Первый запуск»: заведите администратора системы. Пароль
   администратора в коде не лежит – его задаёте вы.
3. Войдите, выберите компанию, создайте и сохраните документ, скачайте PDF.

Если вместо сайта написано «Откройте сайт по защищённому адресу» – сайт
открыт по `http://` или по IP. Откройте адрес с `https://` и доменом.

## 8. Обновить сайт

На своём компьютере – новый пакет (шаг 4), на сервере:

```bash
tar -xzf /opt/docflow-НОВЫЙ.tar.gz -C /opt
sudo bash /opt/docflow/deploy/setup-server.sh
```

Скрипт увидит, что настройки уже есть, и только пересоберёт сайт – на
свежих базовых образах, с исправлениями уязвимостей. Вручную то же самое –
`cd /opt/docflow/deploy && docker compose build --pull && docker compose up -d`.

Настройки `.env` и сертификаты сохраняются. Данные пользователей в их
браузерах обновление не трогает.

## 9. Остановить или убрать

```bash
cd /opt/docflow/deploy
docker compose down          # остановить
docker compose down -v       # остановить и стереть сертификаты
```

## Защита от подбора пароля

Пароль на сайт проверяется медленно (bcrypt, около секунды на попытку), но
сам по себе перебор не останавливает. Поэтому скрипт установки ставит
**fail2ban**: он читает журнал запросов `deploy/logs/access.log` и после
**10 неверных паролей за 10 минут** закрывает адрес на час, при повторах –
дольше, до недели. Правила – `deploy/fail2ban/`. Заодно fail2ban защищает
вход по SSH.

```bash
fail2ban-client status docflow-caddy                  # кто закрыт сейчас
fail2ban-client set docflow-caddy unbanip 1.2.3.4     # открыть адрес
```

Если скрипт написал «защита от подбора пароля не включилась» – вручную
(Ubuntu/Debian):

```bash
apt-get install -y fail2ban
cp /opt/docflow/deploy/fail2ban/docflow-caddy.filter.conf /etc/fail2ban/filter.d/docflow-caddy.conf
sed "s#@LOGPATH@#/opt/docflow/deploy/logs/access.log#" \
  /opt/docflow/deploy/fail2ban/docflow-caddy.jail.conf > /etc/fail2ban/jail.d/docflow-caddy.local
systemctl restart fail2ban && fail2ban-client status docflow-caddy
```

Что ещё стоит сделать на сервере самому (скрипт этого не трогает, чтобы
не закрыть вам доступ):

- **Вход по SSH – только по ключу.** Добавить свой ключ
  (`ssh-copy-id root@IP`), проверить, что вход по ключу работает, и в
  `/etc/ssh/sshd_config` выставить `PasswordAuthentication no`, затем
  `systemctl restart ssh`.
- **Обновления безопасности – автоматически:**
  `apt-get install -y unattended-upgrades`.
- **Только IPv4.** Не добавляйте домену AAAA-запись (IPv6): запросы по IPv6
  Docker передаёт от своего имени, и fail2ban не увидит, откуда подбирают
  пароль. Имя sslip.io и так только IPv4.

Журнал запросов (`deploy/logs/access.log`) хранится до 90 дней, по 10 МБ в
файле. Пароли в него не попадают – вместо них `REDACTED`.

## 10. Если что-то не так

| Что видно | Причина | Что сделать |
|---|---|---|
| Сертификат не выдаётся, в журнале `challenge failed` | Домен ещё не указывает на сервер или закрыт порт 80 | Проверить `nslookup` (шаг 2) и порты (шаг 3), затем `docker compose restart` |
| `required variable DOCFLOW_... is missing` | Не заполнен `.env` | Шаг 5 |
| Сборка обрывается словом `Killed` | На сервере не хватает памяти для сборки (1 ГБ впритык) | Добавить подкачку: `fallocate -l 2G /swapfile && chmod 600 /swapfile && mkswap /swapfile && swapon /swapfile`, затем снова `docker compose up -d --build` |
| Пароль сайта не подходит | Хеш без кавычек, и `$` съелись | Вставить хеш в одинарных кавычках, `docker compose up -d` |
| «Откройте сайт по защищённому адресу» | Сайт открыт по `http://` или IP | Открыть `https://домен` |
| После обновления видна старая версия | Кеш браузера | Ctrl+F5 |
| С одного компьютера сайт перестал открываться (соединение сброшено), с других работает | Адрес закрыт fail2ban после неверных паролей | Подождать час или `fail2ban-client set docflow-caddy unbanip АДРЕС` |
| Вход пропал, документов нет | Данные браузера очищены или другой браузер | Данных на сервере нет (п. 0); восстановить нечем |

## 11. Другой путь: через git

Когда репозиторий на GitHub станет приватным, сервер может брать код оттуда
вместо архива. На сервере создайте ключ и добавьте его в GitHub:
репозиторий → Settings → Deploy keys → Add (только чтение).

```bash
ssh-keygen -t ed25519 -f ~/.ssh/docflow_deploy -N ''
cat ~/.ssh/docflow_deploy.pub
GIT_SSH_COMMAND='ssh -i ~/.ssh/docflow_deploy' git clone git@github.com:MirasDavletaly/DockFlow.git /opt/docflow
```

Дальше – шаги 5–7; обновление – `git pull` и
`sudo bash /opt/docflow/deploy/setup-server.sh`.
Тесты при этом на сервере не идут: запускайте `npm run check` у себя перед
`git push`.
