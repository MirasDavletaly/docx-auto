# Промпты для работы с Claude

Порядок: первый запуск → по одному этапу → независимое ревью этапа → исправления → следующий этап.

Каждый этап лучше начинать в новой сессии: так модель не тащит за собой устаревший контекст, а всё нужное берёт из `CLAUDE.md`, `PROGRESS.md` и плана этапа.

---

## 1. Первый запуск (один раз)

```
Прочитай CLAUDE.md, docs/architecture.md, docs/roadmap.md и catalog/source/documents-list.txt.

Код пока не пиши. Подготовь:

1. Список противоречий, пробелов и рискованных мест, которые ты видишь в архитектуре и плане. Для каждого — почему это проблема и что предлагаешь.
2. Вопросы ко мне, без ответа на которые нельзя начинать этап 0 или которые дорого исправлять потом (схема данных, модель прав, нумерация, юридические моменты).
3. План этапа 0 в docs/plans/phase-00.md.
4. Пустой PROGRESS.md со структурой: «Текущий этап», «Сделано», «В работе», «Не сделано», «Известные проблемы».

Остановись после этого и жди моих ответов.
```

---

## 2. Запуск этапа

```
Выполни этап NN из docs/roadmap.md.

1. Прочитай CLAUDE.md, PROGRESS.md и описание этапа. Запусти make check и зафиксируй исходное состояние.
2. Напиши план в docs/plans/phase-NN.md: файлы, миграции, эндпоинты, тесты, риски, вопросы. Покажи его мне и жди «ок».
3. Работай маленькими шагами: шаг → тесты → make check → коммит. Для каждого нового эндпоинта сначала тесты изоляции компаний и доступа.
4. Обновляй PROGRESS.md после каждого завершённого пункта.
5. В конце — отчёт по формату из раздела 7 CLAUDE.md, с реальными командами и результатами. Всё, что не сделано или не проверено, должно быть видно в отчёте.
```

---

## 3. Продолжение после перерыва

```
Продолжаем этап NN. Прочитай CLAUDE.md, PROGRESS.md и docs/plans/phase-NN.md, посмотри git log --oneline -20 и запусти make check.

Коротко напиши, где мы остановились и что сломано (если сломано), затем продолжай с первого незавершённого пункта плана.
```

---

## 4. Независимое ревью этапа (в новой сессии)

```
Ты ревьюер. Код этого этапа писал не ты, и твоя задача — найти в нём проблемы, а не подтвердить, что всё хорошо.

Проверь ветку этапа NN против CLAUDE.md (раздел 3 «Неприкосновенные правила») и критериев приёмки этапа в docs/roadmap.md.

Особое внимание:
- изоляция компаний: можно ли получить или изменить данные другой компании;
- доступ: можно ли увидеть чужой документ, черновик о себе, чувствительные данные без права;
- гонки: двойной запрос, параллельное утверждение, параллельная нумерация;
- неизменность утверждённых документов;
- деньги, даты, часовые пояса, сумма прописью;
- утечки: пароли, токены, ИИН в логах или ответах;
- заглушки и TODO, которых нет в PROGRESS.md; тесты, которые ничего не проверяют.

Попробуй сломать систему: напиши атакующие тесты (чужой company_id, чужой id документа, повтор запроса, параллельные запросы, файл не того типа, истёкший или отозванный токен). Запусти их.

Код не исправляй. Запиши результат в docs/reviews/phase-NN.md: каждая проблема — важность (критично / важно / мелочь), файл и строка, как воспроизвести, какой тест это доказывает. Если проблем не нашёл в какой-то области — напиши, что именно проверял.
```

---

## 5. Исправление по ревью

```
Исправь проблемы из docs/reviews/phase-NN.md, начиная с критичных.

Для каждой проблемы: сначала тест, который падает и доказывает проблему, потом исправление, потом make check. Один коммит на проблему.

Если считаешь, что проблема не является проблемой, — не исправляй, а объясни почему в docs/reviews/phase-NN.md.

В конце — список: что исправлено, что оспорено и почему.
```

---

## 6. Добавление раздела в каталог (этап 8)

```
Добавь в каталог раздел «<название>» (номер NN) из catalog/source/documents-list.txt.

Для каждого документа раздела:
- запись в catalog/documents/NN-<раздел>.yaml: тип (шаблон / реестр / загружаемый / внешний), профиль доступа, серия номера, маршрут согласования, срок хранения, разделы показа, отметка «влияет на оплату»;
- если это шаблон: fields.yaml с полями (авто / из справочника / вручную) и template.ru.docx со структурой документа; текст пометь «ЧЕРНОВИК ТЕКСТА — ПРОВЕРИТЬ ЮРИСТУ»;
- если документ уже есть в другом разделе — не создавай дубль, добавь показ в этом разделе.

Не выдумывай реквизиты законов и номера статей. Где нужна ссылка на норму права — оставь поле для юриста.

Проверки: make check-catalog, тесты рендера каждого шаблона × 4 компании, матрица доступа раздела.

В конце выгрузи таблицу документов раздела (документ, тип, профиль, кто создаёт, кто видит, кто утверждает) в docs/catalog-review/NN-<раздел>.md для проверки руководителем раздела.
```

---

## 7. Если что-то пошло не так

```
Остановись. Не исправляй сразу.

1. Опиши, что именно не работает, и как ты это обнаружил.
2. Найди причину: воспроизведи проблему тестом.
3. Предложи исправление и объясни, почему оно устраняет причину, а не симптом.
4. Проверь, нет ли той же ошибки в других местах.

Жди моего «ок» перед исправлением, если оно затрагивает схему БД, модель прав или уже утверждённые документы.
```
