# План: сервер, чтобы через F12 не было видно чужих данных

Источник: «Тест день 3», п. 10: «Нужно работать над безопасностью, чтобы никто
не мог зайти в БД и взять данные. Через F12 всё видно, нужно сделать, чтобы
мало информации там было». Решение человека 25.09: **сервер – следующим
этапом**, до него – только дешёвые меры.

Это шаги 0.4–0.5 этапа 0 и этап 1 роадмапа (`docs/roadmap.md`), собранные
вокруг одного вопроса: что видит браузер.

---

## 1. Что видно через F12 сейчас и почему

Сайт работает без сервера: вся база лежит в браузере, в `localStorage`
(`docflow.local.db`), файлы архива – в IndexedDB.

| Что | Где видно | Чем опасно |
|---|---|---|
| Все компании, документы, персонал, журнал – всех компаний | Application → Local Storage | Кто сидит за этим браузером, видит всё, даже не входя |
| Хеши паролей (PBKDF2, 310 000 итераций) | там же | Пароль можно подбирать без ограничения попыток |
| Кто вошёл – идентификатор пользователя | Application → Session Storage | Подмена идентификатора = вход под другим человеком без пароля |
| Права, роли, изоляция компаний | исходный код | Проверки исполняет браузер, их обходят из консоли |

Это не ошибка, которую можно исправить в браузере. Пока данные и проверки
живут на стороне пользователя, пользователь ими управляет. Шифрование в
браузере обсуждали и отложили: ключ всё равно оказывается там же, а забытый
пароль единственного администратора стирает все данные.

## 2. Что сделано сейчас (25.09)

- **Политика содержимого (CSP)** в рабочей сборке (`web/vite.config.ts`):
  скрипты только свои, запросы только к своему адресу, `object-src 'none'`.
  Чужой скрипт, внедрённый в страницу, не загрузится и не отправит данные
  наружу. От человека за этим же браузером это не защищает.
- **Карт исходников в сборке нет** (`sourcemap: false`): через F12 не виден
  исходный код с комментариями.
- **`referrer: no-referrer`**: адрес страницы с идентификатором документа не
  уходит на сторонние сайты (шрифты Google).
- **Вторая проверка прав в сессии** для удаления документов (раньше её не
  было: работник мог удалить документ вызовом из консоли) и для всего нового
  – шаблонов, корзины, выдачи прав.
- Проверено в Chrome: «Скачать PDF», логотипы, шрифты и выгрузка в Excel
  работают под этой политикой.

## 3. Что изменится с сервером

| Сейчас | С сервером |
|---|---|
| Вся база в браузере | В браузере только то, что на экране, и только то, что разрешает роль |
| Хеши паролей в браузере | Пароли – argon2id на сервере, в браузер не уходят никогда |
| Вход – идентификатор в `sessionStorage` | Access-токен 10 минут в памяти, refresh – `httpOnly` cookie, которую скрипт не читает (`CLAUDE.md`, п. 3.8) |
| Изоляция компаний – фильтр в браузере | `company_id` из токена, Row-Level Security в PostgreSQL: запрос не вернёт чужую строку даже при ошибке в коде (`CLAUDE.md`, п. 3.1) |
| Права проверяет браузер | Политика в `internal/access` и фильтр в SQL; браузер только прячет кнопки |
| Файлы архива в IndexedDB | MinIO по подписанным ссылкам, SHA-256, антивирус до выдачи (`CLAUDE.md`, п. 3.7) |
| Удаление навсегда – в браузере | Роль приложения без `DELETE` на аудит; стирание – отдельная процедура со сроками хранения |

Через F12 после этого видно: свой токен в памяти вкладки, ответы API по
открытому экрану и код сайта. Чужих компаний, чужих документов и паролей
в браузере нет.

## 4. Шаги

Каждый шаг – тесты вперёд, `make check`, коммит (`CLAUDE.md`, п. 4).

1. **Среда** (нужен человек, см. п. 5): Docker, Go amd64.
2. **0.4 Инфраструктура**: `infra/docker-compose.yml` – PostgreSQL 16,
   PgBouncer, Redis, MinIO; `/readyz` проверяет базу.
3. **0.5 Миграции**: `goose`, роли БД (приложение без `BYPASSRLS`), тест
   `up → down → up`.
4. **0.7 OpenAPI**: `api/openapi.yaml`, генерация Go и TypeScript.
5. **Этап 1**: компании, пользователи, вход, токены, `token_version`,
   блокировка после 5 попыток, rate limit, RLS, аудит. Тест на каждый
   эндпоинт: пользователь компании А не читает, не меняет и не узнаёт о
   данных компании Б.
6. **Перенос сайта на API** по экранам: вход → компании и персонал →
   документы → шаблоны → архив. `localStorage` остаётся только для языка
   интерфейса. Данные из браузеров переносятся разовой выгрузкой в JSON и
   загрузкой на сервер администратором.
7. **Файлы**: MinIO, подписанные ссылки, проверка содержимого, антивирус
   (этап 5).

## 5. Что нужно от человека

- **Среда разработки** (`PROGRESS.md`, «Известные проблемы»): Go собран под
  `windows/386` – нужен `windows/amd64` или Go в WSL2; Docker не
  запускается – нужен WSL2 и Docker Desktop.
- **Где будет работать сервер.** Персональные данные работников (ИИН,
  адреса, оклады) по закону Республики Казахстан о персональных данных
  хранятся в базе на территории Казахстана (подтвердить у юриста). Нужен сервер компании или
  облако с размещением в Казахстане. Это решение человека, до него
  боевой запуск невозможен.
- **Домен и сертификат HTTPS** для боевого адреса.
