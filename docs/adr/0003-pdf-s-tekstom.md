# ADR 0003. PDF документа – с настоящим текстом, а не картинкой листа

- Статус: принято, заменяет решение ADR 0001
- Дата: 2026-10-12
- Основание: просьба 12.10: «когда скачиваешь документ, там фото вместо
  текста, переделай его на текст»

## Контекст

По ADR 0001 «Скачать PDF» снимал каждый лист в картинку (`html2canvas-pro`)
и клал её на страницу PDF (`jspdf`). Текст в таком файле нельзя выделить,
скопировать и найти поиском, файл весит около 1 МБ на страницу. Человек
прямо попросил текст.

Серверного конвертера (`.docx` → PDF из снимка значений, этап 4) ещё нет:
документы пока живут в браузере.

Лист на экране – HTML, набранный Times New Roman: колонки на трёх языках по
выключке, переносы, шапка с логотипом, таблицы форм с рамками, листы,
разорванные посреди строки тела.

## Варианты

1. **`jsPDF.html()`.** Внутри – тот же `html2canvas`, только рисует он не в
   картинку, а командами PDF. Выключку и переносы он повторяет плохо, а шрифт
   с казахскими буквами всё равно нужно встраивать отдельно.
2. **Свёрстать PDF заново из модели документа (pdf-lib, pdfmake).** Вторая
   вёрстка того же бланка: колонки, выключка, переносы, раскладка по листам.
   Первая же правка бланка разведёт экран и файл.
3. **Перенести в PDF вёрстку, которую уже сделал браузер.** Каждое слово
   листа ставится в PDF текстом в ту же точку, где оно на экране (браузер
   отдаёт место каждого слова), рамки – линиями, логотип – картинкой. Шрифт
   в PDF должен совпадать с Times New Roman по ширине знаков.
4. **Ждать серверный конвертер.** Человеку нужно сейчас.

## Решение

Вариант 3.

- **Шрифт – Tinos** (Google, SIL Open Font License 1.1): сделан по меркам
  Times New Roman. Проверено по файлам: ширина каждого знака и высота строки
  совпадают с Times New Roman из Windows до сотых долей, казахские буквы
  ә ғ қ ң ө ұ ү һ і есть во всех четырёх начертаниях. Сам Times New Roman
  положить в сайт нельзя – он принадлежит Microsoft.
  Файлы – `web/src/assets/fonts/tinos-*.ttf`, взяты из
  `github.com/google/fonts`, `ofl/tinos` 12.10.2026; SHA-256:
  - regular `60a0e8ef0c04dd5dd69ffe91025fa2ae5836cbd35600a82ba031977557e2cb61`
  - bold `393269dbab8899f938db19783eca5eac92eb431f7ae0ab45b8349ca895f1a06b`
  - italic `5942266ed398b155d7dc23e36833e7ec6be988f2439bdbeb8ef1bede808eaa91`
  - bold italic `a5de79f0fe863ea0954757acb3d47b3ccd0a930ce3dd5b97230cd3866790a06e`
- Tinos стоит в листе **запасным** после Times New Roman. Где Times New Roman
  есть (Windows, macOS), браузер файлы для листа не скачивает; где нет
  (Linux, Android), лист набирается Tinos и строки рвутся там же.
- **jsPDF** остаётся: он встраивает в файл только использованные знаки
  шрифта и пишет карту Unicode – текст выделяется и ищется.
- **`html2canvas-pro` удалён**, а с ним – исключение по хешу в политике
  содержимого (`style-src` теперь только `'self'`).
- Дефис переноса браузер в текст страницы не кладёт, но отдаёт его место
  отдельным прямоугольником у двух соседних букв; по нему дефис ставится в
  PDF туда же.

Новых пакетов нет: jsPDF уже стоял, Tinos – файлы шрифта.

## Последствия

- Текст в PDF выделяется, копируется и ищется; казахские буквы – текстом.
  Файл 100–230 КБ на документ вместо ~1 МБ на страницу. Сборка – доли
  секунды.
- Проверено в Chrome на семи документах (приказ на 1 и на 5 листов,
  доверенность, накладная З-2, счёт, КП, акт Р-1), в том числе с
  включёнными словарями переносов и на листе вне экрана (скачивание из
  архива): страницы PDF совпадают с листом на экране, расхождение – меньше
  1 % площади листа, и это сглаживание линий, а не сдвиги текста.
- Переносится то, из чего состоит бланк: текст, фон, сплошные рамки,
  картинки, обрезка `overflow: hidden`. Тени, градиенты, скругления и SVG
  в PDF не попадут – в листе их нет; появятся – этот код надо дополнить.
- Монограмма (компания без логотипа) в PDF набрана Tinos, а не шрифтом
  интерфейса.
- Первое «Скачать PDF» загружает шрифты – до 2,2 МБ, если в документе все
  четыре начертания; дальше они в кеше браузера.
- Это по-прежнему **не** выпущенный документ: у файла нет контрольной
  суммы в системе. Настоящий PDF с SHA-256 собирает сервер из снимка
  значений – TODO(phase-04). Когда он появится, кнопка будет отдавать
  серверный файл, а эта сборка уйдёт.
