# ADR 0001. PDF документа собирается в браузере картинкой листа

- Статус: заменено ADR 0003 (2026-10-12): PDF собирается с настоящим текстом,
  `html2canvas-pro` удалён
- Дата: 2026-09-23
- Основание: «Тест день 2», пункт «Документы сохранить в PDF невозможно без печати»

## Контекст

Сохранить документ в PDF можно было только через окно печати браузера:
«Печать» → «Сохранить как PDF». Человек просил кнопку, которая сразу отдаёт
файл.

По архитектуре (CLAUDE.md, п. 3.4 и 3.6) настоящий PDF выпущенного документа
собирает сервер: конвертер в контейнере без сети рендерит `.docx` из снимка
значений, считает SHA-256 и кладёт файл в хранилище. Сервера пока нет –
сайт работает на данных в браузере.

Лист на экране – это HTML: три колонки на трёх языках, логотип, казахские
буквы, кегли в пунктах. Файл должен совпадать с ним.

## Варианты

1. **Оставить окно печати.** Ничего не добавляет, но человек прямо сказал,
   что это неудобно.
2. **Собрать PDF из модели документа с текстом (jsPDF без HTML или pdf-lib).**
   Текст в файле был бы настоящим, но вёрстку бланка – три колонки по
   выключке, шапку с логотипом, подпись – пришлось бы написать второй раз,
   отдельно от листа на экране, и встроить шрифт с казахскими буквами
   (Times New Roman распространять нельзя, нужна замена). Две вёрстки одного
   бланка разойдутся при первой же правке.
3. **Снять каждый лист в картинку и положить на страницу PDF
   (html2canvas-pro + jsPDF).** Файл совпадает с листом на экране, потому что
   это и есть лист на экране. Текст в файле – изображение: его нельзя выделить
   и найти поиском, файл тяжелее.
4. **Ждать сервер.** Правильный PDF будет только с конвертером (этап 4), а
   кнопка нужна сейчас.

## Решение

Вариант 3 – как временная копия для удобства, до серверного конвертера.

- `jspdf` 4.2.1 (MIT) – собирает PDF из картинок страниц.
- `html2canvas-pro` 2.4.5 (MIT) – снимает лист в картинку. Выбран
  поддерживаемый форк: исходный `html2canvas` не обновлялся с 2022 года и не
  понимает современные цветовые функции CSS.

Обе библиотеки грузятся лениво, только по нажатию «Скачать PDF», и в основную
сборку не входят. `npm audit` новых уязвимостей не показал; остаются две
умеренные в `react-router-dom` (docs/questions.md, Q25).

`jspdf` тянет необязательные `html2canvas`, `canvg` и `dompurify` для своего
метода `.html()`. Мы его не вызываем; эти пакеты попадают в отдельные ленивые
части сборки и не грузятся.

## Последствия

- Файл совпадает с листом до буквы, включая казахские буквы и логотип.
  Проверено в Chrome: документ на 2 листа A4 → PDF на 2 страницы A4.
- Текст в файле не выделяется и не ищется. Размер – около 0,8–1 МБ на
  страницу (240 точек на дюйм, JPEG).
- Это **не** выпущенный документ: у файла нет контрольной суммы в системе,
  и он собирается из того, что на экране. Настоящий PDF с SHA-256 собирает
  сервер из снимка значений – TODO(phase-04). Когда он появится, кнопка
  «Скачать PDF» будет отдавать серверный файл по подписанной ссылке, а эта
  сборка уйдёт вместе с обеими зависимостями.
