# DocFlow

Система документооборота для группы из четырёх компаний в Казахстане: документы
создаются из шаблонов, проходят согласование и утверждение, получают номер,
подписываются и хранятся с учётом сроков.

Сейчас идёт **этап 0 — каркас**. Бизнес-логики ещё нет.

## Требования к машине

- Go — последняя стабильная версия, **сборка amd64**.
- Docker с поддержкой Linux-контейнеров (на Windows — через WSL2).
- Node.js 20+ и менеджер пакетов для сайта.
- GNU make.

Проверить окружение:

```sh
go version      # должно быть amd64, не 386
docker info     # демон должен отвечать
make --version
```

## Запуск

```sh
cp .env.example .env
make dev        # поднять окружение (появится на шаге 0.4)
make run-api    # запустить только api
```

Проверить, что сервер отвечает:

```sh
curl -s localhost:8080/healthz    # {"status":"ok"}
curl -s localhost:8080/readyz     # 503, если недоступна зависимость
curl -s localhost:8080/version
curl -s localhost:9090/metrics    # показатели, отдельный адрес
```

## Проверки

```sh
make check      # всё, что должно быть зелёным перед словом «готово»
make test       # только тесты сервера
make lint
```

`make check` — единственный источник правды о состоянии кода. Ничего не
называется готовым, если он не запускался (CLAUDE.md, п. 5).

## Устройство

```
api/          контракт OpenAPI — из него генерируются типы для сервера и сайта
backend/      сервер на Go: cmd/<процесс>, internal/<пакет>, migrations, queries
web/          сайт на React + TypeScript
catalog/      разделы, профили, роли, серии, документы и шаблоны — это данные
infra/        docker-compose, конфигурация nginx, postgres, redis, minio, мониторинг
docs/         архитектура, план работ, ADR, планы и отчёты по этапам
tests/        изоляция компаний, матрица доступа, гонки, шаблоны, e2e, нагрузка
```

Процессы: `api` (HTTP), `worker` (фоновые задачи), `relay` (outbox → очередь),
`scheduler` (расписание), `converter` (docx → pdf), `migrate`, `seed`.
